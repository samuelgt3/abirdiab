# Languages (English / Arabic)

## How the language is chosen
`SiteContext` reads `localStorage abir_lang`, otherwise the browser language (`ar*` ⇒ Arabic), otherwise English.
The header toggle switches it and sets `<html lang dir>` (`rtl` for Arabic). Switching needs no reload.

## Two kinds of text
| Kind | Lives in | Edited by |
| --- | --- | --- |
| Fixed interface text (headings, buttons, about, FAQ, policies) | `src/content/en.json`, `ar.json`, `policies.json` | a developer (it is code) |
| Business content (courses, workshops, journal, testimonials) | database, `field` + `field_ar` | the client, in `/admin` |

To change fixed text edit the JSON and keep both files' keys identical. `npm run build` will not catch a missing Arabic key; the page would
show nothing for it, so compare the two files after editing.

## Rules for right-to-left
- Use **logical** Tailwind classes: `ms-* me-* ps-* pe-* start-* end-* text-start`, `border-s`, `rtl:` variants — never `ml/mr/left/right` for layout.
- Directional icons (→) get `rtl:-scale-x-100`.
- Arabic headings use Tajawal, body Almarai; `index.css` raises line-height (1.95) and removes letter-spacing for Arabic.
- Numbers stay Western (0-9) to match the original design.
- Keep sentences in JSON whole (do not concatenate fragments) so word order can differ per language.

## Fallback
`pick(row, 'title', lang)` returns `title_ar` only if it is non-empty, else `title`. An untranslated item therefore still shows.

## Adding a third language
Not designed for it (twin columns). It would need a translations table — see [ADR 0004](adr/0004-bilingual-twin-columns.md).

## Translation review
Arabic strings were carried over from the original design unchanged. A native-speaker proofread of any new text is recommended.
